# V2 Offline Results

LM0 0.3 introduces contextual literals, local result-type inference, block-local
register names, compact inspection, and revision-checked replacement. The
compiler remains GNU x86-64 assembly; the new evaluator and execution driver
are C. The compiler links only libc; the evaluator additionally uses json-c.

The committed [report](../../evaluation/v2-report.json) was produced with:

```sh
make eval
build/lm0-eval export build/evaluation-v2
build/lm0-eval report build/evaluation-v2 -o evaluation/v2-report.json
```

The export contains 222 exact artifacts. Baseline programs and the archived v1
generation contract come from the preceding implementation, commit `6b1766c`.
The source corpus is eight examples, including the game engine; generation and
repair prompts cover the existing 20 tasks and 10 repair categories.

| Measurement | V1 Bytes | V2 Bytes | Reduction |
| --- | ---: | ---: | ---: |
| Complete source, eight programs | 24,070 | 19,667 | 18.3% |
| Full inspection in both versions | 10,988 | 9,684 | 11.9% |
| V1 full to v2 compact inspection | 10,988 | 6,343 | 42.3% |
| Block replacement text | 1,076 | 886 | 17.7% |
| Generation contract | 3,873 | 3,236 | 16.4% |

Inspection figures use the current compiler's full and compact views, including
its new instruction guidance and revision hashes. They compare retrieval
workflows, not the historical compiler's output. Diagnostics embed source paths,
so reproducing exact context sizes requires the same export directory name.

These are UTF-8 byte measurements. No tokenizer counts or real model trials were
supplied; token savings, generation accuracy, and model cost are unknown. The
report retains null token fields and contains no invented model attempts.
The evaluator supports importing exact-text measurements and saved trials to
test these hypotheses using the [evaluation protocol](../evaluation.md).

Validation passed: `make smoke`, the 118-test regression suite, and rebuilding
the compiler/evaluator plus exporting/reporting with Python absent from PATH.
V2 migrations preserve executable results and pass numeric boundary, memory,
control-flow, recursion, and C ABI fixtures. The C oracles match all existing
reference cases. Synthetic evaluator tests cover syntax errors, wrong answers,
successful repairs, deadlines, and mismatched token hashes; they are validation
fixtures rather than evidence about model behavior.
